# RFC-0402: Storeback HTTP 402 Micropayment Protocol Specification

**Status:** Standards Track  
**Version:** 1.0.0  
**Editors:** Digitaura Protocol Working Group  

## 1. Abstract
This document specifies the wire protocol for negotiating machine-to-machine micropayments for structured data over HTTP status code 402 ("Payment Required") using the XRP Ledger (XRPL) as the settlement layer.

## 2. Challenge Handshake
When an unauthenticated agent makes a `GET` or `POST` request to a protected Storeback endpoint without an authorization proof:

The server MUST respond with `HTTP 402 Payment Required` and the following mandatory headers:
- `WWW-Authenticate: x402 realm="Storeback Sovereign Data Vending"`
- `X-402-Version: 1.0`
- `X-402-Slug: <resource-slug>`
- `X-402-Price-Drops: <integer>` (1 XRP = 1,000,000 Drops)
- `X-402-Price-XRP: <decimal>`
- `X-402-Recipient-XRPL: <r-address>`
- `X-402-Nonce: <hex-encoded-crypto-nonce>`
- `X-402-Expires: <unix-timestamp>`
- `X-402-Digest: <sha256-hmac>`

## 3. Settlement Verification
The client delivers funds on-chain to `X-402-Recipient-XRPL` referencing `X-402-Nonce` in the `InvoiceID` or `Memos` field.
The client resubmits the request with:
`Authorization: x402 tx_hash=<hex> nonce=<nonce>`

The host verifies:
1. Transaction hash has not been previously redeemed (Replay Protection).
2. Delivered amount >= requested drops.
3. Destination address matches operator wallet.
